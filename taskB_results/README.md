# 의뢰서 B 결과: 전체 모형의 고정 x 계열

의뢰서: `request/REQUEST_B_ko.md`. x = 2 log2(1/z)/N 을 고정하고 Q_un(N, z) − (N/2)σ∞(x) 를 N에 대해 본다.
이 폴더에는 요약(summary.csv, 사다리 파일, 검증 비교)만 있다. 원시 시계열은 보관 브랜치에 있다(맨 아래).

## 1. 결과 요약

`fixedx_table.csv` (`scripts/fixedx_table.py` 로 생성). 오차는 시드 간 산포(`pt_analyze.py`: 시드 평균들의 표준편차/√시드수).

- 수렴한 7개 점은 모두 목표 오차 ±0.02 이하이고, 차가운/뜨거운 시작이 오차 안에서 맞는다.
- N=48의 두 점은 씨앗 8개다. 씨앗 1–4로는 x=0.5 오차가 ±0.026이라 씨앗 5–8을 더 돌렸다.
  씨앗 1–4 / 5–8 따로: x=0.5 15.548 / 15.586, x=0.3 9.348 / 9.350.
- 의뢰서의 작은 계 정확값과 같이 보면:
  - x = 0.7: −1.23, −1.31, −1.31 (N = 12, 16, 20, 정확) → −1.28 (24), −1.19 (32). 대략 일정하다.
  - x = 0.5: −1.43, −1.70, −1.85 (정확) → −1.89 (32), −1.73 (48). N = 32 근처에서 꺾인다.
  - x = 0.3: −1.33, −1.80, −2.19 (정확) → −2.93 (32), −3.15 (48), −3.02 (64). 단조가 아니다.
    N = 48 값은 씨앗 8개, 두 독립 묶음, 차가운/뜨거운 시작이 모두 맞아 통계 문제는 아니다.
    수렴 여부는 N = 96 (z = 4.63e-5) 없이 판단하기 어렵다.
    (검토 추가, 2026-11-25) 경계 모형과의 차 D = Q_un(전체) − Q_un(경계)로 보면 꺾임은 모든 x에서 N* = xN ≈ 14에
    있고, 극한값은 `scripts/full_vs_boundary/README.md`의 경계 자유에너지 계산이 준다.
- 의뢰서의 11개 점 가운데 돌리지 않은 것: x = 0.7, N = 48 (z = 8.76e-6)과 N = 96의 두 점(x = 0.3, 0.4152).
  x = 0.7, N = 48을 뺀 이유는 실행 기록에 없다. 이 z는 평형에 이르지 못한 B64b의 z (1.53e-5)보다 작다. N = 96은
  의뢰서가 앞의 결과를 보고한 뒤 묻도록 한 점이다.

### x = 0.5, N = 64 (B64b): 미수렴

z = 1.53e-5 에서 4×10⁷ 스윕 동안 차가운 시작은 아래로, 뜨거운 시작은 위로 계속 움직였고 만나지 않았다
(`summaries/B64b/drift_x0.5.csv`, 4×10⁶ 스윕 구간 평균).

| 씨앗 | 시작 | 0–4M | 16–20M | 32–36M | 36–40M |
|---|---|---|---|---|---|
| 1 | 차가운 | 31.92 | 30.80 | 27.32 | 25.91 |
| 2 | 차가운 | 31.98 | 29.78 | 26.41 | 25.21 |
| 3 | 뜨거운 | 20.32 | 21.49 | 22.17 | 22.04 |
| 4 | 뜨거운 | 19.95 | 21.14 | 21.16 | 21.16 |

평형값은 21.2 < Q_un < 25.2 사이로만 말할 수 있다((N/2)σ∞ = 23.06). 아래 끝은 뜨거운 시작 씨앗 4가 16M 스윕 이후
21.16에 머물러 있는 값이다(검토에서 22.0을 21.2로 고침, 2026-11-25). `fixedx_table.csv`에서 이 행은 `converged = 0`이다. `summary.csv` 의 25.44 ± 2.48 은
전 구간 평균이라 쓰면 안 된다. 사다리 바닥 두 간격의 교환 수락률도 0.16–0.26 으로 조건(0.2)에 못 미친다.
과제 A의 N = 64 작은 z 결과(평형 시간 ≳ 10⁸ 스윕)와 같은 상황이며, 이 점과 N = 96 은 지역 갱신으로는
현실적이지 않다. 비국소 갱신(worm/directed loop) 개발 뒤에 다시 하는 것을 권한다.

## 2. 검증 (의뢰서의 정확값 5개)

`validation/comparison.csv`. 정확값은 `taskA_results/scripts/exact_qun.py` 로 다시 계산했다
(`validation/exact_N16_B.txt`, `exact_N20_B.txt`). 각 씨앗 8개, 사다리 0.005–0.125 (12 복제본), 5×10⁵ + 4×10⁶ 스윕.

| N | z | MC Q_un | 정확값 | 차이 |
|---|---|---|---|---|
| 16 | 0.0625 | 4.0619 ± 0.0006 | 4.062255 | −0.5σ |
| 16 | 0.020617311 | 5.6302 ± 0.0009 | 5.630758 | −0.7σ |
| 20 | 0.125 | 3.0197 ± 0.0007 | 3.020105 | −0.6σ |
| 20 | 0.03125 | 5.3561 ± 0.0010 | 5.356425 | −0.4σ |
| 20 | 0.0078125 | 7.3701 ± 0.0024 | 7.367769 | +0.9σ |

처음에는 씨앗 4개였고, N = 16 z = 0.0625 가 −3.6σ, N = 20 z = 0.03125 가 −2.0σ 였다. 씨앗 4개의 산포가
오차를 과소추정한 것으로 보고(과제 A의 N = 20 과 같은 현상) 씨앗을 8개로 늘렸다.

## 3. 코드와 실행 명령

- **바이너리:** `taskA_results/scripts/aztec_pt_taskA.c` (이 브랜치 커밋 5c57005 기준, main a54c1c2 와 같은 파일).
  `scripts/aztec/aztec_pt.c` 에 체크포인트/재개, `AZTEC_INIT=empty`(뜨거운 시작), 복제본 왕복 추적을 더한 판이다.
  `gcc -O3 -march=native -o aztec_pt ../../taskA_results/scripts/aztec_pt_taskA.c -lm` 로 `taskB_results/run/` 에 빌드.
- **사다리:** `scripts/ladder.py` (과제 A 판 + `LADDER_EXTRA` 로 고정 x 의 z 를 사다리에 정확히 넣음, 10자리 출력).
  예측 교환 수락률 erfc(Δln z·σ_n/2) ≥ 목표가 되도록 구간을 나눈다. 실제 사다리는 `summaries/<run>/*.zl`.
- **실행:** `scripts/run_pt_B.sh` (과제 A 의 `run_pt_taskA.sh` 와 같음), 대기열 `scripts/queue_B.sh`:

```bash
cd taskB_results/run && setsid nohup ../scripts/queue_B.sh >> queue_B.log 2>&1 < /dev/null &
```

| 실행 | N | 사다리 (`ladder.py` 목표 수락률, 범위) | 복제본 | 평형 + 측정 스윕 | 블록 | 씨앗 | 사다리에 넣은 z |
|---|---|---|---|---|---|---|---|
| B24 | 24 | a0.4, 2.96e-3 – 0.1 | 13 | 1×10⁶ + 4×10⁶ | 100 | 1–4 | x = 0.7 |
| B32 | 32 | a0.4, 4.25e-4 – 0.1 | 21 | 2×10⁶ + 8×10⁶ | 200 | 1–4 | x = 0.7, 0.5, 0.3 |
| B48 | 48 | a0.4, 2.44e-4 – 0.1 | 28 | 4×10⁶ + 1.6×10⁷ | 400 | 1–8 | x = 0.5, 0.3 |
| B64a | 64 | a0.4, 1.29e-3 – 0.1 | 32 | 1×10⁶ + 5×10⁶ | 125 | 1–4 | x = 0.3 |
| B64b | 64 | a0.45, 1.53e-5 – 1e-3 | 20 | 0 + 4×10⁷ (처음부터 기록) | 1000 | 1–4 | x = 0.5 |

  - 측정 간격 200 스윕(B64b 400). 씨앗 번호 mod 4 = 1, 2 는 차가운 시작, 3, 0 은 뜨거운 시작.
  - 스윕 수는 과제 A 의 같은 N 큰 z 사다리 설정 이상으로 잡았다(N = 48 은 과제 A 1×10⁶ + 3×10⁶ 보다 길게).
    B64b 는 과제 A 의 N = 64 작은 z(고원) 사다리를 z = 1.53e-5 까지 아래로 넓힌 것이다.
- **검증 실행:** 보관 브랜치의 `queue4.sh` (= `validation/queue_val.sh`), 커밋 1f2bb0a (+ 씨앗 추가 947e38b, e4a32ea).
  같은 바이너리와 `ladder.py` 다. 인자 `16|20 SEED a0.35 0.005 0.125 500000 4000000 valB 100 100`.
- **분석:** `python3 scripts/aztec/pt_analyze.py <run>` → `summary.csv`.
  `cd taskB_results && python3 scripts/fixedx_table.py run/B24 run/B32 run/B48 run/B64a run/B64b > fixedx_table.csv`.
